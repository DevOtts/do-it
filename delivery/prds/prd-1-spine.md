# PRD-1: Spine (lane L1)

CONTRACT: delivery/CONTRACT.md v1.0-draft. Squad: spine. Epics: S1, S2, S3, S4, S5. Waves: W0 S1 and S3, W1 S2 and S5, W2 S4 (delivery/00-program-plan.md).

## 1. Summary
The spine is `core/spine/do-it.mjs`: one zero-dependency Node ESM file (recorded default R1, Node 22 floor, ruling D1) built from `core/spine/src/*.mjs` by a zero-dependency bundler `core/spine/build.mjs`. It is the only writer of run state (G-1), the only thing that decides what runs next, whether a row is `VERIFIED`, when a session may stop, what the owner is asked, and when a conductor must hand off. Models work; code decides (principle P1, docs/02).

Thirteen commands exist in v1 (CONTRACT section 3): `init start next record gate answer handoff resume park status meter doctor`, where `doctor` takes `--migrate` and `--install`. Exit codes: 0 ok, 1 failed, 2 needs human, 3 blocked or usage limit (docs/03 section 11).

## 2. Problem and goals
Problem (docs/01 findings F1, F5): the lifecycle plugins each keep their own state, report success from model prose, ask questions mid-run, stop early with open rows, and run into the context ceiling or a usage limit with nothing on disk to resume from.

Goals, each testable:
- Goal 1 One state authority: tampering with `state.json` by anything but the spine is detected (G-1).
- Goal 2 Evidence-backed truth: a row is `VERIFIED` only if its evidence resolves to a file or ID the spine re-reads (G-2, G-3).
- Goal 3 Plan once, ask once: no build without a readiness verdict (G-8); one owner pack with a deterministic terse reply parser (G-16).
- Goal 4 Run to the finish line: the stop-gate refuses with the board at most 3 times without progress, then parks and asks (G-9).
- Goal 5 Survive limits: block at the context ceiling until a handoff exists (G-5); park and resume from state after a usage limit; secrets never leak (G-7).
- Goal 6 Honest failure: FAILED, PARTIAL_FAILURE, ROLLED_BACK, ESCALATED, HANDOFF_FAILED, BLOCKED, PARKED are outcomes with exact tokens, not prose.

Non-goals: no model calls inside the spine except the single cheap routing call that the spine requests from the host when routing is ambiguous (S2); no host names in core/ (G-12); no review-loop convergence logic (P4 owns it, the spine only stores `review:{round,exit}`); no Engine runtime code.

## 3. Users and jobs
| User | Job | Served by |
|---|---|---|
| Owner (Fernando) | send one message, answer one numbered pack, read an honest end report | S2 route and board, S4 pack and reply, S3 verdict |
| Conductor persona (L2) | call `do-it next`, spawn the stage persona, go back to sleep | S2 next, S5 ceiling and handoff |
| Stage plugins (companions, R3) | write `it-result/1` as last act, never touch state | S3 record, S1 schemas |
| Host adapters (L3, L4) | supply spawn, ask, continue, wake hooks; read the spine's contract | S4 render flags, S5 hook contract |
| Release engineer (L5) | run the built file in fixtures and e2e | build output, exit codes, JSON outcomes |

## 4. Solution design (decisions)
Numbering D1..Dn here is local to this PRD; owner rulings are cited as "ruling Dn".

- **D1 Single file from src.** `core/spine/build.mjs` concatenates `core/spine/src/*.mjs` in dependency order into `core/spine/do-it.mjs`, stripping import and export statements; the output has no `import` of a non-builtin module. Source: ruling D1, R1, docs/02 layer 4. Node builtins only (`node:fs`, `node:path`, `node:crypto`, `node:child_process`, `node:os`).
- **D2 Outcome tokens.** Every command prints one JSON line with `outcome` (an uppercase token, for example `STATE_TAMPERED`, `CEILING_BLOCKED`, `PARTIAL_FAILURE`) and `exit` when called with `--json`; human mode prints `OUTCOME: TOKEN` first. Tests assert tokens and exit codes, never prose. Source: CONTRACT section 8 (failure states asserted as outcomes).
- **D3 Atomic writes with a sidecar digest.** Every spine write is temp file in the same directory, fsync, rename. `state.json` has a sidecar `runs/{run_id}/.state.sha256` written in the same step. Every command re-reads state and compares; a mismatch is `STATE_TAMPERED`, exit 1, state untouched. This makes G-1 enforceable rather than a convention. Source: CONTRACT G-1, docs/05 S1 note "atomic writes". Proposed amendment A3.
- **D4 Schemas without dependencies.** `core/schemas/*.schema.json` hold JSON Schema documents (it-result/1, do-it-state/1, events, token-meter, finish-line, owner-pack, settings, ledger; host capabilities belongs to L3). A validator in `core/spine/src/schema.mjs` supports the subset used: type, enum, required, properties, items, pattern, minLength, minimum, additionalProperties, const, oneOf. Errors carry a JSON pointer. Source: docs/05 S1 "JSON-schema validation without dependencies".
- **D5 Settings precedence.** run flag (`--set key=value`), workspace `.do-it/settings.json`, global `~/.do-it/settings.json`, defaults; deep merge by key; `doctor` prints each value and its source. Invalid settings fail loudly (exit 1) rather than being ignored; the probed host behaviour of silently ignoring settings files that fail validation is the anti-pattern (docs/research/11-host-cli-probe.md section 1). Source: CONTRACT section 2 settings.json, docs/03 section 6.
- **D6 No harness names in core/.** The settings default for `host.driver` is `auto` (detected), not a harness name, and the settings schema types it as a string. `doctor --install` and host probing take their names from settings or `--host`. Source: G-12; coordinator ruling that the default is `auto`. Proposed amendment A1 (docs/03 section 6 example still shows a harness default).
- **D7 Home resolution.** `DO_IT_HOME` overrides; else `git rev-parse --git-common-dir` resolves the main checkout so a worktree shares one `.do-it/`; else the current directory. Source: docs/02 "One home".
- **D8 Migration is explicit.** `doctor --migrate` copies legacy folders (`.build-it-reports`, `.fable-it-reports`, `.plan-it`) into `.do-it/` with a sha256 manifest, never moves or deletes originals, and refuses while any run is in flight (a run whose status is not terminal: concluded, ESCALATED, FAILED). Source: ruling D12, docs/02 behavior 4.
- **D9 Routing: rules first.** An ordered rule table (keyword and shape) maps a request to one of five presets; the matching rule id is logged in the `route` event. If no rule matches or two presets tie, `next` returns action `ROUTE_MODEL` (class gather, tier T3) once, and the answer is logged with its reason. Source: docs/02 "Pipeline as data"; preset YAML itself is L2 (P1).
- **D10 YAML subset.** Pipelines are read by a small YAML-subset parser (block maps, block lists, scalars, no anchors, no flow tags); anything else is `PIPELINE_UNSUPPORTED_YAML`, exit 1. Zero dependency forces this (ruling D1). Risk R-4 below.
- **D11 Readiness gate.** `gate build` passes only when `.do-it/plan/READINESS.json` exists, every decision is RESOLVED or DEFAULTED, `preflight.passed` is true, no build slice has `depends_on_owner_answer`, and every credential named in `credentials` resolves through the secrets driver. It is re-read on every `next` (an edit after the gate cannot slip through). Source: G-8, docs/02 behavior 1, ruling D16.
- **D12 Mid-run questions are decided by recommendation.** A result asking a human outside an owner-gate kind is refused (`MIDRUN_QUESTION_REFUSED`); the question's recorded recommendation is applied, logged, and appended to the owner pack as kind `default` for the end report. Source: G-8, docs/02 behavior 1.
- **D13 Stop-gate.** `gate stop` returns exit 0 when every finish-line row is terminal (evidence recorded, or PARKED with a question, or BLOCKED with a reason); otherwise exit 1 `STOP_REFUSED` with the board (about 300 tokens, capped at 1200 characters) and `stop_refusals` incremented. Any row state change since the previous refusal resets the counter. Refusal number patience+1 does not refuse: it sets the run PARKED, writes an owner-pack question, and exits 2. Default patience 3 (ruling D10, G-9). Hosts without a stop hook call the same gate from the conductor checklist (R5).
- **D14 Failure ladder.** `record` of status failed marks the slice FAILED; `next` returns it again one tier up (T3 to T2, T2 to T1, T1 stays T1) with a written reason `retry after FAILED` (satisfies G-4's written-reason rule), once; a second failure sets the slice and run ESCALATED with an owner-pack question. Source: CONTRACT M1, RUN-POLICY escalation.
- **D15 Evidence resolution.** Evidence is `path` (relative to the repo root, must exist), `result:{file}` (a file under `runs/{run_id}/results/`), or `sha256:{hex}` matching an entry in the result's `artifacts[]` whose file exists. At record time the spine stores `evidence_sha256`. `gate verify` re-reads every evidence file and recomputes the hash (never trusts mtime); a mismatch downgrades the row to IMPLEMENTED-NOT-VERIFIED, reopens its finish-line row, and emits `evidence_changed`. Source: G-2, docs/03 section 2.
- **D16 Real versus mock.** A verdict row with `real:true` whose evidence points at an artifact of kind `mock` or `fixture` is refused with `REAL_ON_MOCK` and stored as IMPLEMENTED-NOT-VERIFIED. An unreachable target is recorded as IMPLEMENTED-NOT-VERIFIED and prevents `run_verdict` DONE_ALL_VERIFIED. Source: G-3, CONTRACT section 7.
- **D17 Deploy legs.** A deploy-it result carries `legs[]` of `{leg, state, evidence, compensate}` with state in DEPLOYED_VERIFIED, DEPLOYED_UNVERIFIED, HELD, FAILED, NEEDS_HUMAN (docs/02 "Isolation and deploy"). All legs DEPLOYED_VERIFIED: DEPLOYING to PROVING. Mixed passed and failed: PARTIAL_FAILURE, and `next` returns a ROLLBACK action for each passed leg in reverse order. All compensations succeed: ROLLED_BACK. Any compensation fails: ESCALATED with an owner-pack question. After a fix, DEPLOYING again requires every leg re-verified with evidence newer than the rollback event. Proposed amendment A4 (legs shape).
- **D18 Conclude refusal.** `gate conclude` refuses (`CONCLUDE_REFUSED`, exit 1, reasons listed) with an unaccounted ledger row, a slice in RUNNING, or a pending wake (`wake.json` status scheduled). Pass moves the run to its closing status and sets a `run_verdict`. Source: G-13, ruling D3.
- **D19 Owner pack.** One `owner-pack.json` per run; stages append questions through `pending_human.questions_path` in their result; the spine merges, assigns stable `n` (never renumbered, duplicates by text hash ignored), and computes `pack_id` as the sha256 of canonical question JSON. Source: ruling D7, docs/03 section 5.
- **D20 Reply grammar and determinism.** Clauses: `N answer` (one token), `N: free text` (to the next semicolon or newline), `all except N N` (also accepts commas and the word and). Normalization: Unicode NFKC, CRLF to LF, case-insensitive keywords, collapse spaces; no locale-dependent calls (no `toLocaleLowerCase`, no `Intl`). `all` means each question's recommendation. Answers are validated against `options`; invalid option or unknown N is exit 1. Source: G-16, docs/03 section 5. Proposed amendment A5 (tolerance).
- **D21 Defaults when unanswered.** `answer --finalize` applies `default` to unanswered questions that are `reversible:true` and not kind owner-gate; those answers carry source `default` and an event. Irreversible questions and owner gates stay pending, exit 2. Source: docs/02 behavior 1, docs/03 section 5.
- **D22 Renderers and fallback.** `core/renderers/{html,markdown,native}.mjs`. `answer --render auto` picks by settings `interaction.fallback` (default native, html, markdown) given the adapter flag `--native-max N` (0 when the host has no native ask tool). Native only when questions are at most the flag (4 for the `claude-code` question tool per docs/02 Hosts) and each question has 2 to 4 options; otherwise html; if the html file cannot be written, markdown. HTML is a single self-contained file with every dynamic string escaped, no external resource. Source: ruling D7, CONTRACT section 6. The codex `request_user_input` is flagged and unverified in `exec` (docs/research/11 section 6), so the spine never assumes it.
- **D23 Ceilings.** `gate ceiling --ctx-tokens N --window W`: WARN at N at least 150000 or N/W at least 40 percent; BLOCK at N at least 250000 or N/W at least 60 percent; whichever fires first (ruling D4, ruling D3). BLOCK writes `state.ceiling = BLOCKED`; `next` returns exit 3 `CEILING_BLOCKED` until a handoff newer than the block exists (G-5).
- **D24 Handoff.** `handoff` writes `runs/{run_id}/handoff.md` (resume prompt, state file list validated to exist, next action, board, last 5 events), increments `handoffs` (counts attempts, success or not), then in mode auto invokes the host's continue hook. Hook contract: executable named by env `DO_IT_HOST_CONTINUE`, called with the handoff path as its only argument, exit 0 means a fresh conductor started. Non-zero: `HANDOFF_FAILED` exit 1, retry allowed. When `handoffs` reaches `handoff.max_per_run` (5) on a failure, or a sixth attempt is requested: ESCALATED, owner-pack question, exit 2. No hook: mode falls back to ask, the one-line command is printed, exit 2 (CONTRACT section 6). Source: M3, ruling D13. Proposed amendment A2 (hooks stay host-supplied; core names no host).
- **D25 Park and resume.** `park --reason usage_limit --reset-at ISO` sets PARKED, writes `park.json` (resume.state_files, next_action, reset_at), then calls the wake hook: executable in env `DO_IT_HOST_WAKE`, args `at` and a prompt file path, exit 0 and a wake id on stdout; result recorded in `wake.json` with status scheduled. No hook: `wake.json` status unavailable, output says "no wake: parked; run do-it resume after the reset", exit 3. `resume` works from a fresh process using state alone, refuses before `reset_at` unless `--force` (exit 3), re-queues RUNNING slices without counting an attempt, re-verifies every VERIFIED row by hash (D15), and marks the wake consumed. Source: M1 PARKED, docs/research/11 section 7 (scheduling support differs per host; whether ScheduleWakeup works in `-p` or `--bg` sessions is unknown, so the hook is opaque to the spine).
- **D26 Secrets drivers.** `core/drivers/secrets/{file,env,aws-secrets-manager,onepassword}.mjs`, one interface `resolve(name, ref)` returning `{ok, length}` plus an in-memory value held only for redaction. file reads `.secrets/NAME`; env reads `process.env`; aws runs the user's `aws secretsmanager get-secret-value --secret-id REF/NAME --query SecretString --output text`; 1password runs the user's `op read` on the reference. The spine bundles no SDK. Settings and `.env.example` hold references and names only. Whether `aws` and `op` are installed on the build machine is unknown (not in ENV-FACTS.md), so their live behaviour is IMPLEMENTED-NOT-VERIFIED unless the owner supplies credentials; stub-CLI cases cover the invocation contract. Source: ruling D16, G-7.
- **D27 Redaction.** Every value the process resolves is held in a redaction set; anything the spine writes (events, handoff, pack, briefs, results it copies, stdout, stderr, child stderr) passes through `redact()` which replaces a value with `[REDACTED:NAME]` and emits `secret_redacted` with the name only. Source: G-7.
- **D28 Missing credential is a plan-time blocker.** READINESS `credentials` are resolved at `gate build`; a miss gives run BLOCKED, a BLOCKED finish-line row with a reason naming the credential and provider, exit 3, before any slice starts. Source: docs/02 behavior 1, ruling D16.
- **D29 Events and meter fields frozen.** events.jsonl rows have exactly ts, run_id, slice_id, stage, persona, tier, model, host, event, parent_id, verdict; token-meter rows add tokens_in, tokens_out, cache_read, cache_write, estimated, source (provider, estimate, unknown). `meter` append rejects a row without `source`. Writers are the spine only (G-6 behaviour is tested by P2; the field freeze is here). Source: ruling D17, docs/03 section 4.

## 6. Acceptance criteria
1. All five Test Contracts pass 100 percent with evidence (CONTRACT section 7); the [REAL] cases: 30 run the built `core/spine/do-it.mjs` as a child process in a temp directory that is also a real git repository, never an in-process stub.
2. `node core/spine/build.mjs` is deterministic: two builds are byte-identical; the output file imports only `node:` builtins.
3. A grep of `core/` for the harness names listed in the S1 test returns zero hits (G-12), and a grep of every file the spine wrote during the S5 lifecycle fixture for the sentinel secret returns zero hits (G-7).
4. Every failure state in CONTRACT section 8 owned by the spine is asserted as an outcome token: FAILED (T-S2-16), ESCALATED (T-S2-17, T-S3-17, T-S5-07), PARTIAL_FAILURE (T-S3-15), ROLLED_BACK (T-S3-16), HANDOFF_FAILED (T-S5-06), BLOCKED (T-S2-15, T-S5-15), PARKED (T-S2-12, T-S5-09). STALLED and OVER_BUDGET are produced by the P4 controller; the spine only stores `review:{round,exit}`, so their cases are owned by P4.
5. Cascade classes: partial-failure T-S3-15; rollback T-S3-16; failed-recovery to escalation T-S2-16 and T-S2-17, T-S3-17, T-S5-07; recovery/resume T-S3-18, T-S3-19, T-S5-11; adversarial-verify T-S1-01, T-S2-18, T-S3-10, T-S4-16, T-S5-12.

## 7. Risks
| # | Risk | Mitigation |
|---|---|---|
| R-1 | The single-file bundler drifts from the src modules | build is deterministic and tested; the [REAL] cases run only the built file |
| R-2 | Wake hooks differ per host and some cannot wake (docs/research/11 section 7: codex partial, opencode none) | hook is opaque; unavailable gives PARKED plus a documented message; tested both ways |
| R-3 | aws and 1password CLIs may be absent or unauthenticated | driver contract tested with stub CLIs; live runs are IMPLEMENTED-NOT-VERIFIED until the owner supplies access |
| R-4 | The YAML-subset parser rejects a valid L2 preset | the parser is specified by a fixture of the five L2 presets; any rejection fails S2 and is reported to L2 |
| R-5 | Reply grammar edge cases (free text containing digits) | semicolon or newline terminates free text; golden corpus of 25 replies |
| R-6 | Hand-edited state files by well-meaning users | STATE_TAMPERED names the sidecar; no repair command in v1: recovery is restoring from the handoff or re-running `start` |
| R-7 | Token estimates for the board size check | the check uses characters (1200), not tokens; no usage number is claimed |

## 8. Repo and branch plan
Lane L1 only (CONTRACT section 5): `core/spine/**` (src, build.mjs, do-it.mjs output, test/), `core/schemas/**`, `core/renderers/**`, `core/drivers/**`.

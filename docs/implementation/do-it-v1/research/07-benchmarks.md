## 2. Published findings on multi-agent failure and cost
- Anthropic [P]: agents ~4x chat tokens, multi-agent ~15x; token usage explained ~80% of BrowseComp variance; Opus-lead + Sonnet-subagents beat single Opus 4 by 90.2% on internal research eval; early failures: 50 subagents for simple queries, duplicated work from vague delegation, endless search, status-update chatter; lead saves plan to external memory beyond 200k tokens; resume-from-error + retries + checkpoints; effort-scaling rules in prompts; detailed delegation briefs (objective, output format, tools, boundaries). https://www.anthropic.com/engineering/multi-agent-research-system
- Cognition, June 2025 "Don't Build Multi-Agents" [S]: share context, actions carry implicit decisions; parallel subagents produce incompatible work. https://cognition.com/blog/dont-build-multi-agents
- Cognition, Apr 22 2026 follow-up [P]: parallel-writer swarms still don't work; what works = single-threaded writes with multi-agent intelligence: clean-context reviewer (~2 bugs/Devin PR, ~58% severe), smart-friend escalation (needs strong primary), manager+children, read-only subagents. Needs a coder<->reviewer bridge to avoid loops. https://cognition.com/blog/multi-agents-working
- MAST [P abstract]: 14 failure modes, 3 clusters (system design, inter-agent misalignment, task verification), 1,600+ annotated traces over 7 frameworks, kappa 0.88; failures mostly design/misalignment not raw model weakness. Mode names not retrieved. https://arxiv.org/abs/2503.13657
- Claude Code docs [P]: teams use "significantly more tokens"; recommend 3-5 teammates, own disjoint files, start with research/review; unattended teams risk wasted effort. https://code.claude.com/docs/en/agent-teams

## 3. Ten design lessons for do-it
1. Single writer, many readers. Exactly one agent mutates the working tree at a time; parallelism only for read-only research, review, verification (Cognition 2026, Claude docs file-conflict advice).
2. Disk is the memory, not the context window. A state directory (e.g. `.do-it/`) holds run.json, stage artifacts, event log, evidence ledger. Any fresh session resumes from it (Anthropic external plan memory, Ralph, OpenHands event log, LangGraph checkpoints).
3. Stages are idempotent and record-once. Each stage writes `result.json` + status; resume skips completed stages and re-runs only the in-flight one (Temporal, LangGraph idempotency guidance). Resume must auto-find latest state (MS AF critique).
4. Explicit handoff contracts. Each delegation brief = objective, inputs (file paths), output schema, tools, boundaries, budget (Anthropic). Handoffs are written files, not chat memory (MAST inter-agent misalignment).
5. Gates are data, not vibes. Human gates (plan approval, deploy approval) are `gate-*.json` records with status pending/approved/rejected + who/when; headless runs stop with exit code and a resumable state rather than guess (LangGraph interrupt, Jules plan approval). Deploy gate fails closed.
6. "Done" is a lookup in an evidence ledger, verified by a fresh-context verifier that did not write the code (Cognition clean reviewer; MAST task-verification cluster; superpowers verify-before-claim). Verifier runs commands itself; claims without a logged command output = UNVERIFIED.
7. Scale effort to task size. Triage step picks lane (trivial: single agent, no plan; standard; large: plan + review wave) to avoid 15x token spend on small tasks (Anthropic 50-subagent failure).
8. Token discipline by construction. Progressive disclosure (short skill bodies, references loaded on demand), per-stage budgets, pass paths not contents, summaries bounded; plugin metadata costs context every turn so ship few, well-described skills (Claude plugin docs, SKILL.md spec).
9. Tier models by stage and escalate on failure (Aider architect/editor, Anthropic Opus lead + Sonnet workers, Cognition smart-friend only with strong primary). Model is a config key, never hardcoded.
10. Git is the undo and audit trail: branch/worktree per run, commit per verified step, PR as the review gate; reconcile stage compares ledger vs repo vs deploy at the end (Aider, superpowers, Copilot agent).

## 4. Steal / avoid
Steal:
- Spec Kit: artifact chain + per-host command generation; `analyze` cross-check.
- Kiro: requirements with acceptance criteria -> tasks traceability.
- superpowers: bootstrap skill, per-host packaging, post-compaction reinjection, subagent-per-task with 2-stage review, worktrees.
- Ralph: fresh-context inner loop on a file-backed task list, with max-iterations and completion promise.
- LangGraph: interrupt/resume semantics, thread id = run id.
- OpenHands/Temporal: append-only event log, replay without redoing LLM calls.
- Claude Code headless: `--output-format json`, `session_id`, `--json-schema`, `--max-budget-usd`, `--bare` for deterministic runs.
- Anthropic: effort-scaling rules, delegation brief template, tool-description self-repair.
- Copilot/Jules: PR as gate; branch protection as policy.
Avoid:
- Parallel writer swarms and agent-to-agent free chat (Cognition, Claude teams caveats).
- Hard dependency on experimental features (agent teams, no `-p` support, no resume of teammates).
- Persona theatre / giant always-loaded prompts (BMAD) and unverifiable performance claims (Ruflo).
- Host-specific hooks as the only enforcement path; unattended infinite loops without budget caps (Ralph).
- Letting the implementing agent grade its own work.
- Requiring a server/DB (Temporal, LangGraph hosting) for the base plugin.

## 5. Portability recommendation
Strategy: file-based contract + thin per-host adapters (confirms the instinct; also what superpowers and Spec Kit effectively do).
- Layer 1, canonical (host-neutral, 90% of the value): `skills/<stage>/SKILL.md` per agentskills.io spec (one stage each: prompt, plan, build, review, deploy, conclude, reconcile, plus `do-it` router), AGENTS.md for shared rules, `.do-it/` state directory with JSON-schema'd files (run.json, stages/<n>/{brief,result}.json, gates/, ledger.jsonl, events.jsonl) and a tiny dependency-free CLI/script (`scripts/doit-state` in node or sh) that is the ONLY writer of state (atomic write, lock, schema validation, `next` command that prints the next action). Any LLM that can read files and run a shell can drive it, including DeepSeek or custom runtimes.
- Layer 2, adapters (thin, optional, each <100 lines): Claude Code (`.claude-plugin/plugin.json`, agents/, Stop/TaskCompleted hook that calls `doit-state check`), opencode (JS plugin on `session.idle` / `tool.execute.before`; reads SKILL.md natively), Codex (AGENTS.md + `codex exec` runner mapping gates to approval_policy), generic runner (`doit run --host <cmd>`: a shell loop that invokes any CLI headlessly with the stage brief, reads result.json; Ralph-style fresh context per stage).
- Layer 3, enforcement: gates and "done" enforced by the state CLI (exit codes), not by prompt politeness; hooks are an accelerator where available, and the CLI check is the fallback everywhere.
- Capability negotiation: adapter writes `host.json` (can_subagent, can_hook, can_headless, model tiers); skills degrade (no subagents -> run reviewer as a fresh headless invocation).
- Packaging: generate per-host files from one source (like Spec Kit integrations) in CI; test with a conformance suite (run a fixture task end-to-end on each host, compare ledger). Pin skill frontmatter to the spec subset; put non-standard fields under `metadata:`.
- Risks: SKILL.md consumption differs per host (activation heuristics); `allowed-tools` is experimental; headless flags drift across versions - pin and feature-detect (Claude exposes `capabilities` in system/init).

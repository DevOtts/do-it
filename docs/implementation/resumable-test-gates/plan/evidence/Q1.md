## Design notes (crown-jewel choices)
- **Lock**: an owner-populated temp dir renamed onto `.lock`, so `.lock/` never exists without `owner.json`. A steal goes through a `.lock.steal` mkdir mutex and re-checks the owner identity under it, so a fresh lock is never stolen. A missing or corrupt owner is stolen only after 10 s. A live owner's start time is checked only after the lock has been held 30 s. Unlock renames before it removes. Scratch dirs whose pid is dead are swept under the lock.
- **Liveness outside the lock**: "dead" and "start time differs" are permanent for a file, so the scan judges liveness lock-free with one batched `ps -o pid=,lstart= -p a,b,c` and reclaims by `unlink`. Only the winning unlinker prints the line, and reclaim never sends a signal.
- **Strict FIFO**: only the lowest live seq reads signals. Under the lock the head re-checks that no lower ticket name exists and recomputes held from `holders/`, then admits with write + rename. If a holder dies inside that window the head stays conservative and waits one more poll.
- **Swap-out window**: the 5 s wait is paid only when every other condition would admit, and never past the deadline. If the window is incomplete the gate is not admitted (`swap-out to stop (measuring)`), never admitted on a guess.
- An exclusive gate (undeclared peak) reserves the whole budget and skips only condition 3 (`avail ≥ peak`), because it has no declared number. Pressure and swap still guard it.
- If a waiter finds its own ticket gone (quarantined or tampered), it rewrites the ticket with the same seq so it keeps its FIFO place.

## Proposed CONTRACT amendments / readings
1. **`gateQueueCmd` and `gateQueueAdmit` are async (they return Promises).** Waiting has to stay signal-aware (T-Q1-14 rollback), and Q2's tracking and forwarding while the command runs cannot be done inside a synchronous `cliMain`. V1 must let `cliMain` pass a thenable result through (`await` in the bundle footer) for `gate queue` and for `gate run`'s self-admission.
2. **Release is a lock-free `unlink` of the caller's own holder file** (PRD D2/Q2-04 say "under the lock"). Removing a holder only lowers held memory, so any interleaving with an admission check is safe (a checker that still sees it is conservative). This also lets `release()` be synchronous for `gate run`'s `finally`.
3. **WAIT-TIMEOUT `{reason}`** is the waiting reason without its `(now …)` detail: `memory pressure normal`, `budget`, `3.0 GB free`. This matches T-Q1-03's regex and the docs/03 §4 example.
4. **T-Q1-11 "position line"** is read as a status line starting `[gate-queue] position `. The D12 `enqueued … position p/n …` line is not counted.
5. **Exclusive gate**: condition 3 is skipped (see above). The `enqueued`/`admitted` lines say `peak=exclusive` / `peak exclusive`, and a separate line reads `[gate-queue] peak undeclared: exclusive`.
6. **Linux `pswpout`** is converted with 4 KiB pages (not measurable here; flagged for a later Linux [REAL]). An unknown darwin pressure level is named `level N` and waits.
7. New outcomes for flows that §4.4 does not name: `GATE_QUEUE_RAN` (exit = the command's), `GATE_QUEUE_ADMITTED` (in-process admit), `GATE_QUEUE_START_FAILED` (127).

## Deviations and proposed amendments
- **AM-L1-a (D12 reduction):** rules (b) and (c) of D12 cannot coexist with T-L1-14's deep-equal property for every key: dropping an
  old PASS group changes that key's fold from EXPIRED to NEVER_RUN/invalidated, and dropping rows before a clear point can remove a
  clean FAIL that still holds a file UNSTABLE. Built the exact reduction: drop duplicate start/finish on (type, run_id, file, leg),
  start rows that have a finish, and run rows of runs owning no kept row and no clean row; corrupt lines kept verbatim. Proposal:
  either accept this (growth bounded only by dropped starts/duplicates) or relax the property to the decision projection
  `{reuse, reason}` and then add (b)/(c).
- **AM-L1-b (D2/D11 done segments):** instead of renaming absorbed segments to `results.seg-{n}.done-{bytes}.jsonl` (a second,
  non-atomic step), the base file's first line is a CRC'd metadata line `{"schema":"do-it-gate-base/1","absorbed":{seg:bytes}}`
  written in the same atomic rename as the base. Scan skips absorbed bytes, so a crash after the base rename never presents a
  row twice (this also stops a duplicated corrupt line from voiding extra rows). Previous-generation segments are absorbed again
  (late tails, `[gate-results] N late rows recovered`) and deleted after the next base rename.
- **AM-L1-c (D6 vs D13 step 5):** the scanner does NOT treat a PASS-invariant violation as corrupt (D6 lists "invariant"); it
  keeps the row and the fold turns it into FAIL (reason `pass-invariant`), which is what T-L1-05 requires and is stricter.
- `gatePassInvariant` treats an absent `failure_ref` as null (a Python writer that omits it is not penalised).
- T-L1-16 "temp build" = a temp copy of `core/spine/src` with the `// CRC-GUARD` line removed, imported as source (the bundle
  runs `cliMain` on import, so it cannot be imported as a library).

## Deviations and proposed amendments
- **AM-F1-a (gateWhy, T-F1-15):** a new `readFileSync` in the spec changes the spec's own bytes (a `dep` line) and adds a `tree`
  line, so a strict one-line-per-component diff prints three lines. To meet "exactly one line", a class change subsumes the
  `deps` and `tree` lines it implies (`--why` is informational; the key itself is unaffected). Proposed: write that rule into D24.
- **AM-F1-b (G-6 hardening):** declared `gates.reuse.env_files` are excluded from the hash table, the tree and the blob memo, and
  a closure member that is a declared env file is keyed by its HMAC token, never by a plain SHA-256 of its bytes (D18/D22 would
  otherwise publish a dictionary-attackable digest of `.env` in the manifest `hashes` and the tree).
- **AM-F1-c (D19 literals):** a config literal counts as a CORE reference only when it starts with `./`, `../` or `<rootDir>/` and
  holds no regex metacharacter; an unresolved one marks the CORE wide-all only when it has a module extension (.ts .tsx .js .jsx
  .mjs .cjs .json .py). Without this, the pilot's `testPathIgnorePatterns` / `cacheDirectory` literals made every key WIDE.
- **AM-F1-d (D20):** a `gate-fingerprint` crash anywhere in `gateFpSpine` returns `reason: 'fingerprint-error'` (key null), and
  `installed-unknown` takes precedence over `platform-unknown` when both probes fail (the pytest probe drives both).
- **AM-F1-e (spec bytes):** the test file itself is always a `dep` line (`gateKeyFor` adds it), so the spec's
  own bytes are keyed even if an adapter's closure omits it.
- T-F1-04 uses a fixture adapter dir `core/spine/test/g1/fixtures/f1/adapters/jest/{reporter.cjs,adapter.json}` because
  `core/gates/adapters/` (adapters lane) is not on this branch; the "temp build" mutants in T-F1-03/T-F1-13 import a temp copy
  of `core/spine/src` with the `// CORE-LINE` / `// MEMO-VERIFY` line replaced.
- The CONTRACT §4.6 Node pattern string is built from two literals so the spine's raw-read source lint does not flag it.

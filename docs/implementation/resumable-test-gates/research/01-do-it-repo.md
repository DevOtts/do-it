## 2. Findings

### 2.1 Spine: dispatch, how `do-it gate ...` plugs in, zero-dependency, Node floor

1. **Top-level verbs (12).** `core/spine/src/cli.mjs:30`: `init, start, next, record, gate, answer, handoff, resume, park, status, meter, doctor`. Dispatch site: `dispatch()` switch at `cli.mjs:73-91`; unknown verb throws `USAGE` listing `COMMANDS` (`cli.mjs:89`). Entry is `cliMain()` (`cli.mjs:95-128`): `parseArgs` -> `makeCtx` -> `redactInit` -> `dispatch` -> render. Result shape is `{outcome, exit, ...}`; human render is `OUTCOME: X` plus `key: value` lines (`cli.mjs:61-71`); `--json` emits one JSON line.
2. **`gate` ALREADY exists as a verb family, and it means lifecycle gates, not test gates.** `cmdGate` at `cli.mjs:179-192` routes 7 subcommands: `verify, conclude, advance, build, stop, route, ceiling`. The error text lists them at `cli.mjs:190`. So `do-it gate run|queue|...` is a new subcommand under an occupied family. Adding `case 'run':` (and `queue`, `ledger`) at `cli.mjs:182-188` plus the `subcommands` array at `cli.mjs:190` is the plug point. Every existing `gate *` takes `--run` and calls `selectRunId` (e.g. `gateAdvance`, `cli.mjs:194-201`), which throws `NO_RUN` when `.do-it/runs/` is empty (`state.mjs` `selectRunId`). A pre-push hook has no run, so `gate run` must NOT call `selectRunId`; it only needs `ctx`. Naming option to avoid the semantic clash: a separate top-level verb (`do-it tests ...`) vs `gate run`. The README (§3, §7 P4) chose `gate`; that works mechanically but doubles the meaning of "gate".
3. **Flags.** `BOOL_FLAGS` at `cli.mjs:29` is a closed set (`json migrate install secrets append force finalize help version verbose dry-run`). `parseArgs` (`cli.mjs:32-55`) treats an unknown `--flag` as taking the next non-`--` token as its value. `--resume`, `--clean`, `--tier` etc.: `--resume` and `--clean` MUST be added to `BOOL_FLAGS` or `do-it gate run --resume T2` would swallow `T2` as the value of `resume`. (`dry-run`, `force`, `verbose` already exist.)
4. **Exit-code contract** (`record.mjs:~20` `EXIT_FOR_STATUS`, docs/02:23): 0 ok, 1 failed, 2 needs human, 3 blocked/usage-limit. A queue-timeout ("never admitted without a slot", README §6.1 #3) fits exit 3 (blocked) with an `outcome` like `GATE_QUEUE_TIMEOUT`; test failure is exit 1.
5. **The spine is built into ONE file by a custom bundler.** `core/spine/build.mjs` concatenates `core/spine/src/*.mjs` (sorted, `build.mjs:24-28`), plus `core/renderers/*.mjs` and `core/drivers/secrets/*.mjs`, into `core/spine/do-it.mjs`. Hard rules enforced at build time (not by a separate lint):
   - only `node:` and relative imports (`build.mjs:32-39`: throws `only node: and relative imports are allowed, found <spec>`). This IS the zero-dependency enforcement; there is no other lint, no `dependencies` field (`core/spine/package.json` is 167 bytes, only `scripts`).
   - only named declaration exports, no `export default/{/*` (`build.mjs:40`).
   - **globally unique top-level names across all bundled modules** (`build.mjs:44-47`: `duplicate top-level name X in A and B`). A new module that declares `readLedger`/`writeLedger`/`ledgerPath` collides with `core/spine/src/ledger.mjs:6-20` and breaks the build.
   - schemas embedded as `EMBEDDED_SCHEMAS` (`build.mjs:51-54`), so a new `core/schemas/*.schema.json` is picked up automatically.
   - `core/gates/` (the README's P1 location) is NOT in the bundler's source list. Either extend `build.mjs` `sources` (precedent: renderers, drivers/secrets) or place P1/P3/P4/P6 under `core/spine/src/`. Pieces that must run inside another process (the jest reporter, the vitest reporter) cannot be bundled into `do-it.mjs` at all; they must ship as separate standalone files. The pytest plugin is Python (outside the Node zero-dep rule, but it needs its own packaging).
6. **Mirror.** `scripts/mirror-manifest.json` pairs `core/spine/do-it.mjs -> plugins/do-it/scripts/do-it.mjs`, `core/pipelines -> plugins/do-it/pipelines`, `core/personas`, hooks, SKILL.md. `node scripts/sync-mirror.mjs --check` (exit 0/1/3) is the parity check. Any new shipped directory (e.g. `core/gates/` reporters) needs a new `pairs` row, else the plugin install lacks it. After any `src/` change: `node core/spine/build.mjs` (`docs/implementation/do-it-next/KICKOFF.md:47`), then `sync-mirror --write`.
7. **Node floor.** No `engines` field anywhere (MEASURED: only `core/spine/package.json` plus two fixture package.json files exist; no root package.json). The floor is a decision record: `PLAN-REVIEW.md:13` "`core/spine/do-it.mjs`, Node 22 | installed Node is 22"; `.plan-it/do-it-v1.state.json:46` default "do-it.mjs, Node 22". Installed: v22.23.2. Evidence that Node 22 quirks bite: `node --test <dir>` fails for a bare directory on Node 22, use the glob (`docs/implementation/harness-status-tracking/evidence/ST-01.md:41`).
8. **No lock primitive exists in the spine.** `atomicWrite` = tmp+fsync+rename+dir fsync (`fs-atomic.mjs:10-33`); `appendLine` = plain `fs.appendFileSync` (`fs-atomic.mjs:41-44`); grep for `flock|.lock|O_EXCL|'wx'` over `core/spine/src` and `core/state-stores` returns only a path-guard name rule (`path-guard.mjs:9`). `events.jsonl` relies on single-writer. T-10 (two worktrees append concurrently) and P6 (live-owner lock with PID+cwd) both need a NEW lock primitive (e.g. `mkdir`-lock or `open(...,'wx')` + PID liveness via `process.kill(pid,0)`). `fs-atomic.mjs` is the natural home.
9. **Worktree/home rule.** `ctx.home` = `<main checkout>/.do-it` (`ctx.mjs:27-41`): `gitInfo` computes `common` (git-common-dir) then keeps only `top` and `main` (`ctx.mjs:10-25`); `DO_IT_HOME` overrides. So existing do-it state lives in the working tree (`.do-it/`), NOT inside `.git`. The README's ledger location `$(git rev-parse --git-common-dir)/do-it/test-ledger/` (README §2) is a different root than `ctx.home`. `ctx` does not expose `common`; P1 must call `git rev-parse --git-common-dir` itself or extend `gitInfo` to return it. For a main checkout `main = dirname(common)`, so `common = <main>/.git`; for a bare/odd layout `main` falls back to `top` (`ctx.mjs:20`).

### 2.2 Settings: defaults, merge order, schema, `tiers` = MODEL tiers

12. **Validation happens per layer, before merge** (:143-147) and again on the merged result only when `--set` was used (:166-169). A parse error or schema error throws `SETTINGS_INVALID` exit 1. Secret scan runs first and throws `SETTINGS_SECRET_VALUE` (:134-142) using `settingsLooksSecret` (:36-43): a string value under a key named `value|token|password|secret|api_key|...`, or matching a token shape, or a >=32-char unbroken `[A-Za-z0-9+_=-]` string containing digit+letter. A normal command like `bash scripts/gate.sh --tier T2` contains spaces so it passes; a spaceless 32+ char alnum command would be falsely rejected (unlikely, but note a `gates.*` key must not be named `token`/`value`/`secret`/`ref`-adjacent secret names).

Consequence: for `do-it doctor --set gates.on_train_complete="..."` to work, `gates` MUST appear in `SETTINGS_DEFAULTS` with the three keys defaulting to `null`. A schema-only addition is not enough. So a `.do-it/settings.json` containing a top-level `gates` today fails with `SETTINGS_INVALID ... /gates is not an allowed property` (validator behavior: `schema.mjs` `schemaWalk`, `additionalProperties === false` branch). ### 2.4 Host-level (per machine) state today; StateStore and a ledger store

24. **Host-level state in do-it today is minimal.** Only `~/.do-it/settings.json` (global settings, `settings.mjs:92`) and `~/.do-it/bin/` (installed CLI shim, `install.mjs:19`, overridable with `DO_IT_BIN_DIR`). Everything else is per repo under `<main>/.do-it/` (`runs/<id>/{state.json,.state.sha256,events.jsonl,ledger.json,wake.json,...}`, `finish-line.json`, `plan/READINESS.json`, `settings.json`, `.env.example`; docs/03:57-61). `.gitignore` of init: `.do-it/runs/`, `.secrets/` (`init.mjs:15`). 25. **`StateStore` (`core/state-stores/interface.mjs`)** is the async `get/put/append/list` + content-addressed blobs interface over `runs/{run_id}/...` with backends `local-fs`, `git-branch`, `engine` (`index.mjs:14-23`). Facts that matter:
    - `path-guard.mjs:30-34` accepts ONLY paths under `runs/<run-id>/<file>` (`outside runs/` rejected :24; run-id regex :5). There is no namespace for a repo-wide or host-wide store. A ledger store could be forced in as a fake run id (`runs/ledger/...`), but it is a misuse: store roots are per `.do-it` home, not `git-common-dir`, and `list` returns only immediate children.
    - `append(path,line)` is exactly one line (`interface.mjs:60-66`), implemented by `fs.appendFile` with no lock (`local-fs.mjs:_append`). Atomic on POSIX for small O_APPEND writes in practice, but NOT guaranteed on all filesystems/NFS; no compaction API; no read-modify-write primitive.
    - `put` of >256 KiB goes two-phase through a content-addressed blob + `.pending` marker + ref file (`local-fs.mjs:BIG_PUT_BYTES`, `_put`). Ledger compaction rewrites could hit this path; fine but note a `.pending` sweeper (`recoverOrphans`).
    - It is ESM-async and is NOT part of the bundled spine (`build.mjs` does not include `core/state-stores/`), and nothing in `core/spine/src` imports it (grep: spine uses its own sync `fs-atomic.mjs`). So the CLI cannot use `StateStore` without extending the bundler.
    - Verdict: a ledger store can **conform to the idea** (get/put/append/list; swap backend later - README §9 Q3) but should NOT literally subclass `StateStore` for v1. Recommend a small sibling interface `GateLedgerStore { appendRow, readRows, compact, lock }` in the spine (sync, `fs-atomic`-based), with a `local` backend and a documented shape that `engine`/`git-branch` could implement later. Reuse `canonicalJson`/`sha256Bytes` from `hash.mjs:1-19` for keys.

## 4. Risks and failure modes the plan must model

1. **Bundler constraints break silently late.** A P1-P6 module with a duplicate top-level name or a non-`node:` import fails only when `build.mjs` runs (which every spine test does, `helpers.mjs:15`). Plan an early `build.mjs` smoke on each piece.
2. **Mirror drift.** Four files must stay byte-identical after any spine change: `core/spine/do-it.mjs`, `plugins/do-it/scripts/do-it.mjs`, `core/pipelines/*`, `plugins/do-it/pipelines/*` (`sync-mirror.mjs --check`). A forgotten `--write` ships a plugin without the new verb. New shipped dirs need a manifest row.
3. **`--resume`/`--clean`/`--tier` value-swallowing** (`BOOL_FLAGS` closed set, 2.1 #3) causing `do-it gate run --resume T2` to parse `resume=T2`. Test it.
4. **Settings validation is fail-closed for the whole CLI.** `loadSettings` throws on ANY invalid layer including `~/.do-it/settings.json`; a pre-push hook that loads settings would then block every push on a typo in the global file. P7 (Engine pre-push) must decide: hook calls `do-it gate run` and treats `SETTINGS_INVALID` as a visible failure with a clear message (acceptable) vs silently skipping (violates "fail toward running more"? No - skipping would be wrong; failing loudly is right).
5. **`null` default + `--set`**: without `gates` in `SETTINGS_DEFAULTS`, `--set gates.on_push=...` returns `SETTINGS_UNKNOWN_KEY` (`settings.mjs:160`); with it, `doctor` output changes (every project's `doctor` now lists three `gates.*` rows) and `init` writes them (`init.mjs:39`) - an existing test that snapshots the default entries (s1) may need updating.
6. **Concurrent append without a lock** (no primitive exists). Two worktrees (T-10) + the nightly job + a developer gate can interleave; torn lines are possible on non-POSIX-atomic filesystems or lines larger than PIPE_BUF. Rows must be single `write()` calls, each self-validating (with a per-row checksum), and the reader must skip bad lines (README T-04 already says so).
7. **Host-level queue state in `~/.do-it` without a test seam** will be touched by the do-it test suite (it already sandboxes `HOME`, but a queue implementation that reads real `vm_stat`/`sysctl` must be injectable, T-08/T-14 need fake memory readings). `darwin`-only probes (`kern.memorystatus_vm_pressure_level`, `vm.swapusage`) need a Linux path or an explicit `UNKNOWN -> admit with warning / fail` rule; the zero-dep rule means shelling out via `child_process` (allowed: `node:`).
8. **Process-tree cleanup (T-15)** is not something `cp.spawnSync` gives by default; need detached process groups (`detached:true` + `process.kill(-pgid)`) with Windows out of scope; do-it's hosts are mac/linux only (UNKNOWN for Windows: README of do-it claims hosts, not OSes; I did not verify).
9. **Settings secret scan false positive** on a gate command with no spaces and >=32 alnum chars (2.2 #12). Low probability; document that `gates.*` values are commands, not secrets, and that real secrets go through the secrets driver.
10. **`slice.status = DONE` is not "merged"**; wiring T2-at-last-merge to `DONE` would fire the train gate before the PRs actually land and gate the wrong tree. The trigger must key on git/PR evidence or an explicit owner "train closed" record.
11. **Finish-line is one board per home, not per run** (`finish-line.mjs:12`), so a `gate-train` row id must be run-scoped (e.g. `gate-train:<run_id>`) to avoid colliding with another run's row.
12. **Name collisions** (ledger, `gate`, T1-T3) will cost reviewers; fix names in the plan before the contract freezes (§5).

## 5. Open questions only the owner can answer (with my recommendation)

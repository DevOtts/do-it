### 2.3 Gate slot and heavy-gate

**`scripts/lib/gate-slot.sh` is a COPY per repo, not one shared file.** MEASURED by `git cat-file -e origin/main:scripts/lib/gate-slot.sh` over every checkout: present only in brain-api-core, brain-connectors (md5 `7675e339…`, identical) and brain-apps (md5 `392e2f8d…`, differs by one line: `:48` `{ exec {fd}>"$lockfile"; } 2>/dev/null || continue` vs `exec {fd}>"$lockfile" 2>/dev/null || continue`). There is no `AC:scripts/lib/`. Only those three pre-push scripts call `gate_slot_acquire` (grep count; api-core `:117-119`, connectors `:120-122`, apps `:118-120`). **brain-agent, brain-admin-ui, claude-cli-runner, processor, master-admin, browser-agent, handson-agent, engine-trainning, brain-docs do NOT use it** (0 matches). README §6.1 says "in every pre-push": refuted (3 of 12).

Semantics (`origin/main:brain-api-core/scripts/lib/gate-slot.sh`, 78 L):
- Lock dir `GATE_SLOT_DIR` default `/tmp/engine-gate-slots` (`:32`). Files `slot-1.lock … slot-N.lock`, opened with `exec {fd}>file` and taken with `flock -n -x "$fd"` (`:43-50`). Kernel `flock` is released when the process dies, so **a dead holder frees its slot automatically** (no stale-lock problem; the "33-min stale lock of 2026-10-06" cited in README §6.1 item 4 belongs to heavy-gate's mkdir lock, not this one). Lock files persist at 0 bytes (live: `/tmp/engine-gate-slots/slot-1.lock`, `slot-2.lock`).
- Env vars: `GATE_SLOT_DIR`, `GATE_SLOT_N` default 2 (`:33`), `GATE_SLOT_TIMEOUT_S` default 1800 (`:34`), `GATE_SLOT_POLL_S` default 2 (`:35`). Header says "tests only — production pre-push.sh never sets these" (`:19-24`).
- Contract (`:26-30`): `gate_slot_acquire` ALWAYS returns 0. **The proceed-without-a-slot line is `:64-67`**: `if [ "$waited" -ge "$GATE_SLOT_TIMEOUT_S" ]; then echo "... proceeding WITHOUT a slot ..."; return 0`. README cites `:65`; the `echo` is `:65`, the `return 0` `:66` (MEASURED, close enough). It is a documented design choice (R25: "a concurrency cap must never itself become the reason a push is rejected"), which §6.1 rule 3 reverses. T-12 therefore intentionally contradicts R25 and `scripts/tests/test-gate-slot.sh` (205 L; the "timeout degrade" case asserts success on timeout) must be rewritten, not just the lib.
- Slots count processes, not memory. It counts a 40 s docs gate the same as a 2 h api-core gate.
- **`flock` dependency (ESTIMATED risk)**: macOS ships no `flock`. This Mac has `/opt/homebrew/bin/flock -> ../Cellar/flock/0.4.0/bin/flock` (MEASURED). `flock -n -x "$fd" 2>/dev/null` (`:49`) also fails with exit 127 when the binary is missing, which the loop reads as "slot busy": every slot looks taken, the push waits 1,800 s, then proceeds without a slot. A hook launched with a PATH lacking `/opt/homebrew/bin` would silently degrade. I did not test this (no execution), reading only. The do-it queue should not depend on external `flock` (use `mkdir`/`O_EXCL` + PID, or `node:fs`).
- Live: no holders on either slot file, 0 gate/jest processes (see 2.9).

**`heavy-gate.sh`** (`AC:docs/implementation/0-done/be-claudecode-like/delivery/bin/heavy-gate.sh`, 58 L; only copy, MEASURED by `find`; it lives in an ARCHIVED plan folder, so a doc archival can move it, R28):

Stale reclaim: owner PID dead (`kill -0`) AND no gate process alive (`:42-43`). Release only if owner == `$$` (`:47`). Dir `…/Engine/.locks` exists and is empty now (MEASURED).
- `busy()` = any process whose argv matches `bash …scripts/(git-hooks/)?pre-push(.sh)?|.git/hooks/pre-push` and whose cwd (via `lsof`) matches `brain-(api-core|agent)` (`:21-28`). **Only api-core and agent count as heavy; admin-ui/connectors/apps never block it and are never counted.**
- Swap guard: `SWAP_MAX_PCT` default **75** (`:18`); `swap_high` parses `vm.swapusage` total/used and compares `used*100/total > 75` (`:29-31`). Polls every 30 s, **no timeout, waits forever** (`:35-45`). It does not read `kern.memorystatus_vm_pressure_level`. Also: conductor `HOLD` file at `…/.locks/HOLD` (empty = all wait; a path = only that worktree may go) (`:17,36`); refuses a second gate in the same worktree with exit 3 (`:32-34`); exports `NODE_OPTIONS=--max-old-space-size=8192` (`:50`).

- Gaps vs README §6.1: no children cleanup (relies on pre-push exiting), no memory budget, no FIFO (poll race: whoever polls first wins), opt-in only, hardcoded absolute paths.

4.1 **Coverage vs reuse (diff-coverage).** `diff-coverage.sh` needs lcov for the whole suite (`collectCoverage: true`, lcov concatenated from an in-band real-mongo run and a parallel rest run, then `uvx diff-cover` against changed lines, threshold 60%). A reused PASS carries no coverage. If the ledger skips a file whose closure includes a changed line, the file is NOT skipped (closure changed), so changed-line coverage is intact in theory; but a file whose closure did not change cannot cover changed lines by definition. This argument is sound only when the closure is complete (dynamic requires/`jest.mock` string paths are the leak). Needs an explicit design decision: (a) the diff-coverage leg consumes only files whose closure intersects the diff (is a ledger consumer, not a producer), or (b) it keeps running the full coverage run unchanged and the ledger applies to leg 4 only. `DIFF_COVERAGE_LCOV` (operator-supplied lcov) already exists as the seam.
4.2 **Real-mongo reuse is not pure.** 190 real-mongo files (11-12% of files, 25-32% of summed time) depend on live DB state, the shared `engine-mongo-dev` container, index state and collection leftovers. Results depend on environment, not only closure. Their key needs the Mongo schema/seed fingerprint, or they must be excluded from reuse (always re-run; each is 5-30 s, 153 files = ~244 s warm). `REQUIRE_REAL_MONGO=1` makes a missing Mongo THROW instead of skip (`pre-push.sh:133`); a ledger written outside the gate (plain `npx jest`, where they silently skip) must never record skip as PASS.
4.3 **Specs that read the tree, the git diff or sibling repos.** The 13 ALWAYS_RUN_GUARDS (`readFileSync`/`git ls-files`/`git diff`/dynamic require/`grep -rn src/`) and cross-repo tests that read the sibling's `origin/main` (addendum 2026-11-02 item 3: `tests/parity/h1_matrix.json`, hook-inventory test) have unbounded or external closures. They must be classified non-reusable ("always re-run") in the CORE/guard list; P3's resolver (jest haste map, `--findRelatedTests`) cannot discover them. `assert-untouched.spec.ts` depends on the branch name/diff, so even identical content gives a different answer on a different branch.
4.4 **Closure leaks.** `jest.mock('string')`, `require(variable)`, `fs.readFileSync` of fixtures/JSON/`.md` (module docs, ActionType manifest JSON, `scripts/highway-regression-tests.txt`), `__fixtures__` dirs, snapshot files, `.env` values loaded by `setupFiles: dotenv/config`, `src/common/testing/loopback-default.setup.ts`, tsconfig base file(s). The brain-agent graph misses the same class and covers it with the text rule; the README keeps it. For jest the equivalent is hashing every non-TS file the test text names plus the setup files plus `package.json` deps. ts-jest has no `isolatedModules`, so type information of imported `.d.ts` can change emit (decorator metadata); treat `tsconfig*.json` and `typescript`/`ts-jest` versions as CORE.
4.5 **Working tree vs commit.** The api-core hook tests the working tree, git pushes the commit (addendum 2026-11-02 item 1, backlog `1-backlog/2026-11-02/gate-tests-working-tree-not-the-commit.md`). Reuse by content hash is safe only if the ledger writer and reader hash the same bytes jest read. Refuse to write PASS rows on a dirty tracked tree; brain-agent's `run.sh` already uses a scratch worktree for this.
4.6 **Absolute paths in names**: jest JSON names are absolute (`/Users/macbook/Workspace/Engine/.wt/twv3-*/src/...`); worktrees under `.wt/` and a shared `git-common-dir` ledger means keys must be repo-relative. `testPathIgnorePatterns` and `modulePathIgnorePatterns` already exclude nested `.wt/`.
4.7 **`$(git rev-parse --git-common-dir)` as the ledger home**: gate-stamps already live there (brain-agent). In a linked worktree the hook runs with GIT_DIR unset (`pre-push.sh:75`), so `--path-format=absolute --git-common-dir` is correct (as in `run.sh:68`). `.wt/brain-api-core` and `.wt/brain-agent` are SHARED symlinks in the Engine-Core root (memory note): never write there; a separate ledger per `git-common-dir` is per-repo, fine.
4.8 **Concurrency on the ledger**: two worktrees of api-core push at once (slot count 2) -> concurrent appends; JSONL with `O_APPEND` single-write <PIPE_BUF is atomic on POSIX locally, but compaction needs a lock. The queue serialises heavy gates per machine, so in practice 1-2 writers; T-10 stays.
4.9 **Verdict-token drift**: composed output must integrate with `SKIPPED_LEGS`/`FAILED_LEGS`/`RETRIED_FILES` named-leg machinery (R20) and the final `[OK-…]` lines (`pre-push.sh:849-872`); `rtk` truncation (R30) means evidence is JSON, not stdout. The gate transcript goes to `pre-push-last.log`; a reuse count printed there is fine.
4.10 **Queue timeout semantics change R25**: failing instead of proceeding turns today's "slow push" into "rejected push" for sessions that rely on the unbounded fallback; unattended overnight runs (CLAUDE.md global rules) need the failure to be a RETRYABLE non-code exit, not a [BLOCK] that a conductor treats as a red test. The existing `HOLD` file protocol and "conductor trains" (memory: one heavy gate per machine) must be subsumed or kept compatible.
4.11 **Memory admission signal**: `Pages free` is ~69 MiB on a healthy Mac; admit on pressure level + swap % (heavy-gate's 75% rule is the proven baseline) and measured RSS of running gate processes, not on free pages. The 2026-11-06 09:3x data point (two jest workers 6.6 GB RSS each, 4.5-4.8 GB compressed) shows RSS alone overstates cost; use compressed-aware measure (`footprint`/`memory_pressure`) or empirical per-repo peaks. Doing so would also prevent the whole-run loss the ledger only partially recovers (T-08).
4.12 **Residual flake / pollution**: retry-once already turns a real order-dependent failure into `[RETRIED]`; the ledger must distinguish "passed in isolation retry" (not reusable) from "passed in the batch". maxWorkers=2 means ordering/pollution between files is limited to 2 workers' sequences per run; reuse removes some cross-file orderings (README §4 T3 covers; T3 needs a producer that actually fails: a planted order-dependent fixture per R3).
4.13 **Skipped = not passed.** 9 suites / 48 tests are skipped in every run; treat `skipped`/`todo` as non-PASS rows.

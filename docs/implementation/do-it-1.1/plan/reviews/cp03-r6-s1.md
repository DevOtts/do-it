## 2. New findings

### R6-S1-M13 MEDIUM: a FIFO anywhere on the gate's path outside the registry still hangs the spine. The hook then allows the stop for every home

```
two homes, session ff-s: A open in X, B open in Y (patience 50)
hook ff-s X                                                       → hook=2
mkfifo X/.do-it/.env.example            ; hook ff-s X             → hook=0 after 20 s, stderr "the spine gave no answer, so this stop is allowed unchecked."
mkfifo X/.do-it/plan/READINESS.json     ; hook ff-s X             → hook=0 after 20 s
FIFO in place of X/.do-it/runs/<A>/events.jsonl ; hook ff-s X     → hook=0 after 20 s
FIFO in place of Y/.do-it/runs/<B>/events.jsonl ; hook ff-s X     → hook=0 after 20 s   (the other home takes X down)
patience 1, FIFO at X/.do-it/runs/<A>/owner-pack.json ; 2nd stop → hook=0 after 20 s, run left INTAKE
remove the FIFO                                                   → hook=2
```

R5-S1-M10 gave the registry a regular-file-only, capped reader. Its own comment says "a FIFO, a device or an endless file must never hang the spine". The gate path still has other raw `fs` calls, and any one of them blocks forever on a FIFO:
- `redact.mjs` `redactDeclaredNames`: `readFileSync` of `<home>/plan/READINESS.json` and `<home>/.env.example`. It runs from `redactInit` in `cli.mjs:118`, before any command, `gate stop` included.
- `fs-atomic.mjs` `appendJsonLine`: `appendFileSync` on `events.jsonl`. Opening a FIFO for writing blocks until a reader appears. Every refusal appends `stop_refused`, in every home that is gated.
- `pack.mjs` `packAppend` and `openPackQuestions`: `readJsonIfExists` reads `owner-pack.json` and `answers.json` with plain `readFileSync` (the patience path).
- Off the hook path, the same raw reads are in `stopGateMarks` (`events.jsonl`) and `readQuestionsFile`.

A blocking syscall cannot be broken by the spine's own timer. The hook's 20 s `spawnSync` timeout then fires, `json` is null, and the hook exits 0. That allows the stop for the cwd's run and for every registered home: the R4-S1-M7 containment ("a broken other home never opens the cwd run's gate") is broken from the inside.

- **Origin:**
  - The single-home hang is **pre-existing 1.0.x**. At d38cedb, `redactDeclaredNames` (bd2f3264) and `appendFileSync` in `appendLine` were already there.
  - That one home's FIFO opens the gate of the other homes is a **new 1.1 surface**: the multi-home gate (R3-S1-H7) and the round-5 claim.
- **Hand-made artefact:** yes, a FIFO in `.do-it/`. That is the same precondition as R5-S1-M10, so it gets the same grade. **Exotic host:** no.

Fix:
- Route every read the spine does through `readRegularFile` / `readJsonRegular`: `readJsonIfExists`, `redactDeclaredNames`, `stopGateMarks`, `readQuestionsFile` and `readiness.mjs:35`.
- Route every append through a regular-file check:
  1. `lstat` the file (ENOENT is fine).
  2. Open it with `O_WRONLY|O_APPEND|O_CREAT|O_NONBLOCK`. A FIFO with no reader then fails with ENXIO and does not block.
  3. `fstat` it and refuse anything that is not a regular file.
  4. `eachRefusal` already contains a per-run throw, so a bad events file fails open for its own run only.
- Add a source lint test: no `fs.readFileSync`, `fs.appendFileSync` or `fs.openSync` outside `fs-atomic.mjs`.
- Regression test: run the five commands above through the shipped hook. Each must exit 2, and the cross-home case must still refuse X.

### LOW

- **R6-S1-L1, new 1.1 surface (05fc689 and 26e52ed).** The R5-S1-L1 placeholder rule is bypassed through a slice.
  - The sequence: write `READINESS.json` with one slice, run `gate build` (→ BUILDING), then record `{slice_id:"s1", status:"blocked", reason:"."}`. A reason of only U+200B behaves the same.
  - Result: `BLOCKED`, `status_reason "every remaining slice is blocked: s1 (.)"`, and the hook exits 0 with 10 of 10 rows open.
  - `blockReason` checks the slice reason with `trim()` only. The guard then runs `cleanReason` on the sentence the spine built around it, and that sentence always passes.
  - Fix: `blockReason` (and `failReason`) return `cleanReason(...)`. The settle cause should be built only from cleaned slice reasons.
- **R6-S1-L2, pre-existing 1.0.x (`_spine.mjs` spawnSync, same line at d38cedb).** A refusal larger than 1 MiB fails open.
  - `spawnSync` has a default `maxBuffer` of 1 MiB. A plan of 25,000 slices (agent-authored `READINESS.json`, no hand edit to spine files) makes `gate stop` print 1,251,720 bytes. The child is cut off with ENOBUFS, and the hook exits 0 with "the spine gave no answer".
  - 12,000 slices (601,720 bytes) is still refused.
  - Fix: set `maxBuffer` to 64 MiB in `callSpine`. Clip `board` and `open` in the gate's JSON (count plus the first N ids). Treat `r.error.code === 'ENOBUFS'` as a refusal, since only a refusal is that long.
- **R6-S1-L3, pre-existing 1.0.x.** The R5-S1-L2 wrong-shape check covers only a non-array `rows`.
  - `{"rows":[null]}` → `INTERNAL_ERROR "Cannot read properties of null (reading 'state')"`, and the hook exits 0. d38cedb gives the same INTERNAL_ERROR.
  - `{"rows":[1,2]}` → `STOP_ALLOWED`.
  - It needs a hand edit of the board. A valid-shape `{"rows":[]}`, or re-tagging the rows with an uppercased run_id, also allows the stop.
  - The row deletion is caught downstream: `next` re-adds the rows (hook back to 2) and `gate conclude` → `CONCLUDE_REFUSED unaccounted_row`.
  - Fix: in strict mode, every row must be an object with a string `id` and `state`, or the board is FINISH_LINE_UNREADABLE.
- **R6-S1-L4, new 1.1 surface (`cli.mjs:233`).** `gate escalate --reason` checks only `trim()`, so `.` or U+200B is accepted. Run: a NEEDS_HUMAN run with an open question, then `gate escalate --reason "."` → `ESCALATED`, `status_reason {"status":"ESCALATED","reason":"."}`. The run is already non-gating there (NEEDS_HUMAN or FAILED), so no gate is switched off, but the terminal ESCALATED stores a placeholder `status_reason`. Fix: use `cleanReason`.

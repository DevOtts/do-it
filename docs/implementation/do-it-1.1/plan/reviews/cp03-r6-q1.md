## 2. Attacks on the round-5 fixes

### UNSAFE_NAME and quarantine (held)

- **Can a bound file be quarantined?**
  - No. Every name the chain writes is printable ASCII:
    - `modelSlug` = `normalizeModelId(m).replace(/[^a-z0-9.-]+/g, …)`;
    - `ombudsman.md`;
    - `SAFE.md`.
  - So `isUnsafeName` is never true for a bound file.
  - The fold rule in `publish` still excludes the three exact target names.
  - Bound files from an earlier chain (`audit-gemini.md`) do not fold to a current target.
- **HFS+, legit chain, then write `SAFE‌.md`.** HFS+ opens the existing `SAFE.md`, so the write changes its bytes. `status` → `PUBLISHED_TAMPERED: audit/SAFE.md`, exit 1.
- **User's own non-ASCII entries.** I planted `audit/notas-é/` (a directory) and `audit/résumé.txt` during AUDITING:
  - `status` exits 1 with `UNSAFE_NAME` + `PUBLISHED_UNBOUND`.
  - At publish both are moved to `audit/.quarantine/<ts>/`. They are not deleted, and the move is logged.
  - `status` then exits 0 with `files match their hashes`.
  - This is a contract choice and fails closed. One cosmetic note: the log line calls them a `case variant of a published name`, which they are not.
- **A dangling symlink with an unsafe name** (`x‌.md`). `status` exits 1 (`UNSAFE_NAME`). `start --restart --quarantine-published` moves it and starts.

- Only `/\[\d+[km]\]$/` survives: `claude-opus-5-5[1m]`, `[200K]` and `o3[1m]` resolve.
- Every other bracket is refused.
- Fullwidth brackets become `[`/`]` under NFKC and are refused too.

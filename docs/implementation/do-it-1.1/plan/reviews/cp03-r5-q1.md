## 2. New findings that got through

### R5-Q1-M8 MEDIUM: on an HFS+ disk, a planted file whose name holds an ignorable code point opens as `audit/SAFE.md` and is never UNBOUND, so `status` exits 0

Origin: new 1.1 surface. `isPublishedName` comes from 5c6d27d and `foldName` from 58ac22c. This is the R4-Q1-M7 class, and the round-4 residual note ("I know of none on APFS or NTFS") did not consider HFS+.

```
# HFS+ (Mac OS Extended, case-insensitive) image mounted at mnt/
(1) C start claims.md --auditor-model sonnet --repos … → state AUDITING
    printf '<forged SAFE, current ledger sha256, SAFE (2): C1, C2>' > "audit/SAFE‌.md"
    C status --ledger claims.md → "state AUDITING", exit 0
    sed -n 5,9p audit/SAFE.md   → "## SAFE (2) / - C1 — thing one / - C2 — thing two"   (the forged file)
(2) legit chain → PUBLISHABLE (SAFE 1: C1), then forge SAFE.md and
    mv SAFE.md "SAFE‌.md"; mv ombudsman.md "ombudsman‌.md"; mv audit-sonnet.md "audit‌-sonnet.md"
    rm audit/chain-state.json audit/chain-state.sha256
    C start claims.md … → "state AUDITING"  (no PUBLISHED_UNBOUND)
    C status → exit 0;  audit/SAFE.md lists C2 as SAFE
```

How it was found:
- A brute-force probe wrote `SAFE.md`, `ombudsman.md` and `audit-sonnet.md`. For every code point from U+0001 to U+2FFFF, it substituted or inserted that one character at every position (13.8M names), then asked `existsSync`. It reported each name that opens a published file while `isPublishedName` says false.
- On APFS (the default disk here) there were 0 misses, so the round-4 fold is complete for single-character variants there.
- On HFS+ there were 480 misses. All of them are insertions of the code points HFS+ ignores when it compares names: U+200C to U+200F, U+202A to U+202E, U+206A to U+206F, and U+FEFF.
- NFKC keeps these code points, so `foldName('SAFE‌.md')` is not `safe.md`. The file is never listed by `publishedOnDisk`, and every consumer that opens `audit/SAFE.md` reads it.
- HFS+ is still a choice in Disk Utility and is common on external drives. The ledger folder only has to live on one.

Fix:
- In `foldName`, after NFKC, strip `/\p{Default_Ignorable_Code_Point}/gu`. That set covers all 16 code points found here.
- Failing closed is simpler and safer: treat any top-level `audit/` entry whose name is not printable ASCII as a published name. It is then UNBOUND unless a recorded hash names it exactly, and none ever will, because the chain writes only ASCII names.
- Add a regression test with `SAFE‌.md` and `ombudsman﻿.md` that asserts `isPublishedName` is true. On an HFS+ image, also replay cases (1) and (2) end to end and assert that `status` exits 1.

### R5-Q1-M9 MEDIUM: a family word inside brackets, or before an `anthropic/`, `openai/`, `google/`, `meta/` or `xai/` path segment, is erased before the "a word that names a family fixes it" rule runs, so an id that names opus passes G-6 as gemini without any declaration

Origin: new 1.1 surface. The `familyWords` strip comes from 8a0fc5a (the Q1-H1 fix), and the R2-Q1-M4 rule (da4e5fd) never sees the erased words.

```
probe (resolveFamily, no declaration):
  "gemini-2.5-pro[opus]"            → {"family":"gemini"}
  "gemini[claude-opus-5-5]"         → {"family":"gemini"}
  "[opus-5-5]gemini-pro"            → {"family":"gemini"}
  "opus/anthropic/gemini-pro"       → {"family":"gemini"}
  "opus.anthropic.gemini-2.5-pro"   → {"family":"gemini"}
  "opus/meta/llama-3"               → {"family":"llama"}
end to end, opus ledger:
  C start claims.md --auditor-model 'gemini-2.5-pro[opus]' --repos … → "auditor gemini-2.5-pro[opus] … state AUDITING"
  record-audit (model: gemini-2.5-pro[opus]) → accepted; record-ombudsman → "published … SAFE 1, DO-NOT-PUBLISH 1"
  C status → "state PUBLISHABLE … files match their hashes", exit 0
```

Why it gets through:
- `familyWords` runs `s.replace(/\[[^\]]*\]/g, ' ')`, which is meant for context tags such as `[1m]`, and `s.replace(/^(?:[a-z]+[./])*(?:anthropic|openai|google|meta|xai)[./:]/, ' ')`. Both erase arbitrary text, including family words.
- The R2-Q1-M4 check ("any word that names a family fixes the family; two families are refused") and the R3 joined-letters check both read `familyWords`, so they never see `opus`.
- The id resolves as a known `gemini` id, and G-6 compares gemini with opus.

It is graded the same as R2-Q1-M4:
- The auditor id is supplied by the caller (Q1-L1), and the id is still shown in SAFE.md (`auditor gemini-2.5-pro[opus]`).
- It is worse than R2-Q1-M4 in one way: no `--model-family` declaration is needed, so the id resolves silently as a known family.

Fix:
- Strip only a context-size tag: `/\[\d+[km]\]$/` (and `-1m`). Refuse any other bracketed text.
- Strip a vendor path only when every segment before it is a prefix or router word, and run the family scan over the segments that were stripped as well. A family word anywhere in the raw id must fix the family, or count as a second family.
- Add a regression test: `gemini-2.5-pro[opus]`, `[opus]gemini`, `opus/anthropic/gemini-pro` and `opus/meta/llama-3` against an opus author must be refused, and `claude-opus-5-5[1m]` and `us.anthropic.claude-opus-5-5-v1:0` must still be opus.

## 3. Attacks on the round-4 fixes that held

- **Case and NFKC fold on APFS.** The brute force (all single-character substitutions and insertions, U+0001 to U+2FFFF, on the three published names) found 0 names that open a published file and are not matched by `isPublishedName`. Long s, Kelvin sign, fullwidth letters and ligatures all fold.
- **Publish over a planted variant.** On APFS this is a round-4 test. On HFS+, a planted `SAFE‌.md` is replaced by the legit publish, which lands as `SAFE.md`. `status` then says `files match their hashes`, exit 0, with the legit content (`SAFE (1)`). So this is not a false pass.
- **Can a legitimate file be quarantined?**
  - `publish` moves only names that fold to one of the three names it is about to write and are not that exact name.
  - Every name the chain records is lower-case ASCII (`modelSlug`) or exactly `SAFE.md`, so a bound file from an earlier chain can never be a variant.
  - Over-folding can move a user's own file, for example `Safe.md` or a fullwidth `ＳＡＦＥ.md`. That file is moved to `.quarantine/`, never deleted, and the move is logged. This is a contract choice.
- **Router prefixes.**

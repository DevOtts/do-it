**M2. A fix for C13 already exists and needs no new code.** `build-it@bea0e4a:plugins/build-it/scripts/status/status-write.mjs:344-366` `cmdClose`: `--move` is optional (`:360 if (flags.move) {…} else say('closed')`), so `status-write close --file docs/implementation/0-done/<name>/status.json --by conclude-it --owner-note "<why>"` closes a board **in place** after a `git mv` archive. The conclude-it wrapper cannot do this: `ledger-card.mjs:327-330` resolves `docs/implementation/<name>/status.json` (not 0-done) and `:339` refuses when `0-done/<name>` already exists. So the three Engine-Core boards are closable today with the build-it writer directly; the gap is only in the S4 path and the wrapper, not the writer.

**M3. Why `owner.session_id` is null, and why 1.0.5's scoping is inert by default.** `do-it@d38cedb:core/spine/src/cli.mjs:141` (and the two embedded copies `core/spine/do-it.mjs:352`, `plugins/do-it/scripts/do-it.mjs:352`): `owner: { session_id: typeof f.session === 'string' && f.session ? f.session : (ctx.env.DO_IT_SESSION_ID || null), cwd: ctx.cwd }`. `git grep -E "start.*--session|DO_IT_SESSION_ID" origin/main -- plugins hosts README.md docs/*.md` → no caller; `hosts/claude-code/hooks/hooks.json` has only `Stop` and `PreToolUse` hooks (no SessionStart), and `plugins/do-it/skills/do-it/SKILL.md:20` says `node core/spine/do-it.mjs start "<request>"` with no session flag. A `start` issued from inside Claude Code therefore always records `session_id: null` and falls to the cwd match (C3), which is exactly the Engine-Core state. The release plan should treat "pass the session id to `start`" (or read it in a SessionStart hook) as the root fix, not only the gate-side status check.

## (a) SessionStart + CLAUDE_ENV_FILE: VERIFIED (documentation), and a simpler path exists

Source: https://code.claude.com/docs/en/hooks.md (docs.claude.com redirects there), fetched 2026-11-06.
- "SessionStart hooks have access to the `CLAUDE_ENV_FILE` environment variable, which provides a file path where you can persist environment variables for the shell commands Claude runs later in the session."
- "Each Bash command runs the file's contents as shell code before the command itself."
- "`CLAUDE_ENV_FILE` is available for SessionStart, Setup, CwdChanged, and FileChanged hooks."
- The SessionStart stdin example includes `"session_id"`.

So step 0 as written would work. But https://code.claude.com/docs/en/env-vars.md documents `CLAUDE_CODE_SESSION_ID`:

> "Set automatically to the current session ID in Bash and PowerShell tool subprocesses, hook command subprocesses … For Bash, PowerShell, and hooks this matches the `session_id` field in the hook JSON input and is updated on `/clear`."

Further evidence:
- It is set in this session's Bash and equals the session id.
- It already worked in Engine-Core (run a6d0, see M3).
- `CLAUDE_ENV_FILE` is *not* set in ordinary Bash, as the docs say, since it is a hook-only variable.

Recommendation: drop the SessionStart hook and the `session-<pid>.json` fallback. `cli.mjs:141` falls back to `ctx.env.CLAUDE_CODE_SESSION_ID`, and `SKILL.md:20` gains `--session "$CLAUDE_CODE_SESSION_ID"` for clarity. S1-00 becomes a test, not a spike. One edge case to test: the id changes on `/clear` (documented), so a run started before `/clear` stops matching its own session. Decide whether that should be STOP_ALLOWED.

## (b) D4 `ref` on github plugin sources: VERIFIED (documentation)

Source: https://code.claude.com/docs/en/plugins/marketplace-reference.md, "Plugin sources", fetched 2026-11-06.
- Table row: "`github` | `repo`, `ref`, `sha` | GitHub repository in `owner/repo` form".
- "**`ref`**: a branch or tag. Defaults to the repository's default branch."
- "**`sha`**: a full 40-character lowercase commit SHA. When you set both `ref` and `sha`, Claude Code checks out `sha`."
- Example: `{"source":"github","repo":"your-org/formatter","ref":"v2.0.0","sha":"a1b2…"}`.
- Also documented: "Claude Code ignores an unknown … plugin-entry key rather than rejecting it", and an entry's `version` loses to `plugin.json`'s.

So D4's premise holds. Caveat for the D4 default: `ref: v<version>` requires that tag to exist. prompt-it has no v1.0.0 (C20, which depends on D3), and do-it has no v1.0.5 (§5 item 14). A `ref` to a missing tag fails the install. Pin `sha` as well, or tag first. T-H1-03 is still worth running as a real install, but it is now a confirmation, not a premise check.

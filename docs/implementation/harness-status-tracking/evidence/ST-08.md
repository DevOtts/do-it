## Residual risks (not fixed)

1. **`--by` is self-declared** (D-05). Anyone can run `set --status verified --by review-it` with a verdict-shaped file they wrote themselves (`review-it` + id + `verdict: PASS`). The same applies to a hand edit plus a forged `by: review-it` history entry plus such a file: the validator re-checks D-06 and passes. Mitigation: review-it signs verdicts with an HMAC (key outside the repo) or records the verdict's sha256 and session id in history; the validator checks against the session ledger.
2. **A never-started task deleted by hand together with nothing else is undetectable**: 2 verified + 1 not-started, delete the 3rd, and the board shows 100% valid. No history exists to cross-check, because init writes none (adding creation entries would change the plan-it/concurrency contracts). Mitigation: the mod compares task ids against the git-committed previous status.json or plan.json; or init writes `created` history entries (contract change: plan-it, tests).
3. **Migration prefix forgery**: on an `approximate: true` file, a forger who rewrites an early migration entry can mark an untouched task `verified` with any non-empty evidence. It still displays "approximate". Partial fix only.
4. **`done` evidence is any non-empty file under the impl folder or any `.taskstate/`**, including the spec or epic itself (D-04 by design). Mitigation: require `.taskstate/` or `evidence/` subpaths, or a test-output signature.
5. **Evidence swap**: `set --evidence` (or a hand edit) can swap a done task's evidence for another valid file. History does not record evidence. Mitigation: store the evidence path and hash in each history entry.
6. **Pieces have no history**, so a hand-edited piece status is caught only for blocked without `blocked_on`. Pieces do not feed the percent.
7. **Lock**: an unreadable or garbage lock with a fresh mtime blocks writers for up to 30 s (exit 3). The three-writer reclaim race is narrowed, not closed.
8. **Huge evidence file** is read whole for the verdict check. No size cap.
9. **computeView** (lib, used by the mod) still returns a numeric percent for invalid docs alongside `errors[]`. The mod must show the errors (follow-up for the doitstatus mod; the CLI `view` and the render now do).

## Attacks that failed (defenses held)

- Role variants `Review-It`, `review-it ` (with a space), `REVIEW-IT`, `migration` and empty: all refused as unknown roles.
- build-it `set --status verified`: refused. init-it or plan-it touching task status or owner: refused. `--by migration` on the writer: refused.
- plan-it `init` with tasks pre-set to verified/evidence/history: the writer forces `not-started`/`null`. Forbidden keys in plan.json: refused.
- `verified` via `init --merge`, `close`, `reopen` or `session`: none of them touches task status. close/reopen only flip `closed` and record `*` history.
- `..` traversal, absolute paths, symlinks out of the repo, directories, FIFOs, empty and whitespace-only evidence: all refused. `./` and `//` normalize to the same file (accepted, harmless).
- A verdict with PASS only in prose: refused. A verdict naming a different task (without a `task:` line): refused. conclude-it carrying forward without a verdict: refused.
- Rounding: 199 verified + 1 done gives 99. 1/1 verified gives 100 (allowed). `closed: true` with done tasks gives 60, not 100. T=0 with closed gives unknown. Blocked counts as 0 and stays listed.
- Schema `"1"` as a string: unsupported. Invalid JSON: clear error. History deleted entirely: every started task flagged.
- A dead-pid lock is reclaimed. A live holder gives exit 3. A leftover tmp is overwritten. Two writers on the same task: valid file, chained history (5 rounds). On different tasks: the existing AT-13 test.
- Migration: `run: ../../etc/passwd`, `/etc/passwd`, a symlink out of the repo and `status.json.lock` all fail to back verified (the task is downgraded). `approximate` is hard-coded true. Never `verified` without a resolvable file.
- Render: no title, newline or HTML-comment trick produces a second `Progress:` line or displaces the first-line marker. flat() already flattened `\n`. ST-08 added ` `, control characters and `<`.
- Docs: neither SKILL.md nor README tells a model to write `verified` or type a percent. Both say the opposite. Added one SKILL bullet (both copies) saying `report` exits 1 with INVALID and must be quoted, not repaired by hand. README rules updated.
- The dogfood board `do-it/docs/implementation/harness-status-tracking/status.json` still validates under the hardened validator (read-only check).
